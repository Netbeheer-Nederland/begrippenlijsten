== Introduction
****
Making use of the CIM to model data for a given application comes with great benefits, such as shared vocabulary and re-use of domain knowledge and modeling expertise -- for both humans and machines. However, applications have more specific constraints and may require additional vocabulary. Furthermore, correctly and usefully making use of the CIM for a given application is not trivial, and guidance may be needed. A specification that describes such constraints and extensions, and which provides guidance about how to apply standards (the CIM in our case) is called an _(application) profile_. For our convenience, profiles of the CIM will be referred to as _CIM profiles_.

In this specification a description will be provided of what CIM profiles are, what their logical structure is and the information contained in them, how to represent them -- both for humans and machines, how to create them and how to validate their correctness.
****

== Definition
A <<dfn-cim-profile,CIM profile>> is a <<dfn-data-profile,data profile>> of the CIM.

.PROF-AP-CIM

Implied in this definition is that CIM profiles are standards^DCTERMS^ (or, synonymously, specifications). Consequently, profiles can be profiled.

****
.Profiling of profiles at Netbeheer Nederland.
====
At Netbeheer Nederland, a CIM profile group has been created to provide a standardized way of using the CIM to model data for given applications. Several specific use cases have arisen, each of which has created a data model by conforming to the profile group. The resulting data model, however, can be regarded a profile in its own right, since it is a data specification which provides constraints, extensions and guidance on how to apply a standard.
====
****

A CIM profile _MUST_ conform to the PROF-AP-CIM specification in order to be regarded valid.

//which conforms to the PROF-AP-CIM specification.

NOTE: Being a profile of the CIM does not exclude being a profile of other specifications as well.

PROF-AP-CIM is an application profile of PROF, and specifies how the CIM ought to be used when modeling data for given applications.

****
More verbosely, this means a CIM profile is a specification that constrains, extends, combines or provide guidance for or explanation about the usage of the canonical CIM and other data specifications to define the content and structure of data used in a given context.
****

=== Resources

PROF-AP-CIM provides resources to help with the creation, validation and use of CIM profiles:

SHACL:: enforces the desired structure of a CIM profile when serialized as RDF
JSON Schema:: helps with authoring profiles in JSON/YAML (including LD) and allows validating
non-RDF JSON/YAML
OWL:: definition of additional PROF-AP-CIM vocabulary not part of PROF or SHACL
JSON-LD context:: syntactic transformations allowing for the mapping between non-LD and LD JSON/YAML and more
comfortable writing of JSON/YAML that is JSON-LD

can be used to validate it. For representations in YAML or JSON which are not utilizing JSON-LD, the JSON Schema can be
